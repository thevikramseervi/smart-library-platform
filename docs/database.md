# Smart Library Platform - Database Design

**Implementation snapshot:** 2026-11-09 (Alembic head `019_return_and_fine_paid_types`)

## Overview

The Smart Library Platform uses **PostgreSQL** managed by **Alembic migrations** in `backend/alembic/versions/`.

This document has two parts:

1. **[Implemented Schema](#implemented-schema)** — tables that exist in migrations today  
2. **[Planned Schema](#planned-schema-not-yet-implemented)** — future tables documented for design reference only  

Do not assume planned tables exist in the database until a migration adds them.

---

# Database Standards

## Primary Keys

Entity tables use UUID primary keys. The many-to-many junction tables
`book_authors` and `book_categories` use composite foreign-key primary keys.

## Timestamps

Most entities contain:

```sql
created_at TIMESTAMP WITH TIME ZONE
updated_at TIMESTAMP WITH TIME ZONE
```

## Soft Deletes

Major business entities use:

```sql
deleted_at TIMESTAMP WITH TIME ZONE NULL
```

Applied to: `users`, `books`, `authors`, `categories`, `publishers` (when deleted via API).

## Role and Status Values (Implemented)

### Role names (stored in `roles.name`; not a PostgreSQL enum)

```text
ADMIN
LIBRARIAN
STUDENT
```

### BookCopyStatus

```text
AVAILABLE
BORROWED
RESERVED
LOST
DAMAGED
RETIRED
```

`LOST`, `DAMAGED`, and `RETIRED` copies are excluded from `available_copies` and cannot be issued. Staff update copy status via `PUT /book-copies/{id}` when the copy is not on loan. `BORROWED` and `RESERVED` are managed by circulation workflows.

### TransactionStatus

```text
ISSUED
RETURNED
```

**Overdue is not stored.** A loan is overdue when `status = ISSUED` AND `due_at < current_date`. API responses include computed `is_overdue`.

> The enum value `OVERDUE` is **not used** in the current schema.

### ReservationStatus

```text
ACTIVE
FULFILLED
CANCELLED
EXPIRED
```

### EmbeddingStatus

```text
PENDING
INDEXED
FAILED
```

Used by `book_embeddings.embedding_status`. Only rows with `INDEXED` and a non-null embedding participate in semantic search.

Book create/update requests mark the row `PENDING` and schedule a targeted
background embedding update using FastEmbed with `BAAI/bge-small-en-v1.5`.
Renaming a linked author, category, or publisher also marks each affected book
pending and schedules reindexing. The admin status view compares content hashes
so stale vectors count as pending. If indexing fails or is interrupted, the row
remains `FAILED`/`PENDING` and can be retried or rebuilt with
`uv run python -m app.scripts.reindex_embeddings`.

| Column        | Type         |
| ------------- | ------------ |

## publishers, languages, authors, categories

Catalog reference tables: publishers (`name`, website, country), languages
(`name`, `code`), authors (`name`, bio), and categories (`name`, description).
Publishers, authors, and categories are soft-deleted; languages have no delete
endpoint. Publisher, language, and category names are unique; language codes
are unique. Author names are not unique.

## transactions

| Column         | Type              |
| -------------- | ----------------- |
| id             | UUID              |
| book_copy_id   | UUID              |
| student_id     | UUID              |
| issued_by      | UUID              |
| returned_by    | UUID (nullable)   |
| reservation_id | UUID (nullable)   |
| issued_at      | TIMESTAMPTZ       |
| due_at         | DATE              |
| renewal_count  | INTEGER (>= 0)    |
| returned_at    | TIMESTAMPTZ       |
| status         | TransactionStatus |
| created_at     | TIMESTAMPTZ       |
| updated_at     | TIMESTAMPTZ       |

Indexes: `(student_id, status)`, `status`, `due_at`, `reservation_id`; partial unique index enforcing one open loan per copy (`status = ISSUED`).

Business rules:

* Issue only when copy status is `AVAILABLE` (or `RESERVED` for the head of the book's queue)
* Return sets transaction `RETURNED` and copy `AVAILABLE`, or copy `RESERVED` when an active queue remains
* `due_at` = issue date + the active policy's `loan_period_days` (default 14); runtime settings are used only when no active policy exists
* Students with unpaid fines cannot borrow (HTTP 409)
* Students cannot exceed the active policy's `max_active_loans` concurrent-loan limit (default 5)
* Students can renew their own active, non-overdue loan when no active reservation queue exists for the book and they have no unpaid fines; each renewal extends the current due date by the active policy's loan period
* Each loan can be renewed up to the active policy's `max_renewals` (default 1; 0 disables renewals); the renewal count is stored on the transaction
* Issue/return serialize on row locks: the student and copy rows are locked `FOR UPDATE` before status checks

## reservations

| Column           | Type              |
| ---------------- | ----------------- |
| id               | UUID              |
| student_id       | UUID              |
| book_id          | UUID              |
| reservation_date | TIMESTAMPTZ       |
| expiry_date      | TIMESTAMPTZ       |
| status           | ReservationStatus |
| created_at       | TIMESTAMPTZ       |
| updated_at       | TIMESTAMPTZ       |

Indexes: `(book_id, status, reservation_date)`, `(student_id, status)`; partial UNIQUE `(student_id, book_id) WHERE status = 'ACTIVE'`.

Business rules:

* Allowed only when no `AVAILABLE` copies exist for the book
* FIFO queue by `reservation_date`; position computed at query time
* One active reservation per student per book (DB-enforced by the partial unique index)
* Cancelling or expiring the last active reservation releases copies held as `RESERVED` back to `AVAILABLE`

## fines

| Column         | Type          |
| -------------- | ------------- |
| id             | UUID          |
| transaction_id | UUID          |
| amount         | DECIMAL(10,2) |
| reason         | VARCHAR       |
| paid           | BOOLEAN       |
| paid_at        | TIMESTAMPTZ   |
| created_at     | TIMESTAMPTZ   |
| updated_at     | TIMESTAMPTZ   |

Constraint: `transaction_id` is UNIQUE from migration `003`. Migration `007`
added a redundant unique index on the same column; migration `014` removes that
index, leaving the unique constraint in place.

Business rules:

* Accrues on overdue open loans when fine lists, dashboards, or borrowing eligibility are read: `(today - due_at)` **calendar days** × the active policy's `daily_overdue_fine_rate` (default ₹10.00/day), clamped to its `max_fine_amount` (default ₹500.00); runtime settings are used only when no active policy exists
* The same fine row is finalized on return using `(return_date - due_at)` calendar days; staff can mark it paid only after the book is returned
* One fine per transaction
* Unpaid fines block new issues
* Payment is exactly-once: a conditional update on `paid = false` makes concurrent double-pays return 409

| daily_overdue_fine_rate | DECIMAL(10,2) |
| max_fine_amount         | DECIMAL(10,2) |
| loan_period_days        | INTEGER       |
| max_active_loans        | INTEGER       |

## notifications

Added in migration `016_in_app_notifications`. Each notification belongs to one
user and has a unique event key per user so repeated reads or concurrent event
processing do not create duplicates.

| Column            | Type          | Notes |
|-------------------|---------------|-------|
| id                | UUID          | Primary key |
| user_id           | UUID          | FK to `users.id`, cascades on user deletion |
| event_key         | VARCHAR(200)  | Unique with `user_id`; idempotency key |
| notification_type | VARCHAR(40)   | `BOOK_ISSUED`, `BOOK_RETURNED`, `RESERVATION_READY`, `DUE_SOON`, `LOAN_OVERDUE`, `FINE_RECORDED`, or `FINE_PAID` |
| title             | VARCHAR(120)  | Short heading |
| message           | TEXT          | User-facing detail |
| link              | VARCHAR(255)  | Optional internal frontend path |
| read_at           | TIMESTAMPTZ   | NULL until read |
| created_at        | TIMESTAMPTZ   | Creation time |
| updated_at        | TIMESTAMPTZ   | Updated time |

Indexes: `(user_id, created_at)`, `(user_id, read_at)`; UNIQUE `(user_id, event_key)`.
Due-soon reminders are created on authenticated notification-center reads for
student loans due today through three days ahead. Overdue alerts are created
once per overdue loan on the same app-driven check. Neither uses a background
scheduler.

Migration `013` inserts a default active policy (₹10/day, ₹500 cap, 14-day
loan, five concurrent loans, seven-day reservation expiry); `015` adds a
default maximum of one renewal per loan. The application
uses the most recently updated active row; if none exists, it constructs a
transient policy from the corresponding environment settings. The schema does
not enforce that only one row is active.

## ratings

Implemented in migration `012_ratings`. One rating (1–5) per student per book.

| Column | Type | Constraints |
| ------ | ---- | ----------- |
| id | UUID | PK |
| book_id | UUID | FK → `books.id` ON DELETE CASCADE |
| student_id | UUID | FK → `users.id` ON DELETE CASCADE |
| score | INTEGER | CHECK between 1 and 5 |
| created_at / updated_at | TIMESTAMPTZ | Standard timestamps |

Unique constraint on `(book_id, student_id)` creates a composite unique index.
Migration `014` also adds separate lookup indexes on `book_id` and `student_id`
to match the SQLAlchemy model metadata.

# Business Rules Summary

| Topic | Current behaviour | Future |
|-------|-------------------|--------|
| Overdue detection | Derived (`ISSUED` + past `due_at`, UTC calendar) | — |
| Fine calculation | Calendar days late × active policy daily rate, clamped to `max_fine_amount` | Working-day calculation via `library_calendar` (planned) |
| Loan limit | Max `max_active_loans` (active policy, default 5) concurrent loans per student | — |
| Circulation policy | Admin UI manages the active rules and records the latest editor; no policy-change history is stored | Multi-tier policies (by patron / material type) |
| Reservation queue | FIFO by `reservation_date`; returns hold copies `RESERVED` for queue head; issues honor queue unless `bypass_reservation` | — |
| Session revocation | Password reset/change bumps `users.token_version`; old JWTs rejected immediately | Token refresh endpoint (planned) |
| Copy QR | `qr_code_value` stored; no QR API yet | Sprint 5+ QR endpoints |
| Book renewal | Students can renew eligible active loans up to the admin-configured limit (default 1); the due date extends by the policy loan period | — |

# Search and Recommendation Notes

Semantic search is implemented: FastEmbed `BAAI/bge-small-en-v1.5` embeddings
(384-dim) are stored in `book_embeddings` and queried by cosine similarity over
an HNSW index. Catalog changes mark affected embeddings pending and schedule
targeted background indexing. Admins can inspect indexing status, retry pending
or failed records, and start a confirmed full rebuild from `/admin/search-index`;
the offline command `uv run python -m app.scripts.reindex_embeddings` is also
available. Search analytics (`search_query_logs`) and recommendations remain
planned.

# PostgreSQL Deployment Notes

## Local development

Docker Compose (`docker-compose.yml`) uses `pgvector/pgvector:pg16`. Migrations enable `pgcrypto`, `vector`, and `pg_trgm` as required.

## Neon

Use connection string with `sslmode=require`. Run `uv run alembic upgrade head` from `backend/`.

Enable `vector` and `pg_trgm` extensions via migrations `005` and `006` (supported on Neon PostgreSQL 16).
